{#- One participant per row -- the infinite-scroll fragment for a single challenge's roster. Included for the first server-rendered page by `admin/challenge_members.html` and re-served bare by `GET /views/admin/challenges/{id}/members/fragment` for every page after it, exactly like `admin/_member_rows.html`. It must therefore stay free of anything but the rows: no wrapper, no empty state, no counter -- `createInfiniteScroller()` counts this file's top-level children to advance the offset. A row **opens that member's profile**, exactly like a row on the member roster, and for the same reason: the next question an operator has about a name in a list is who it belongs to. That the profile is reachable at all is one clause -- `profile_visibility_filter` in routers/user.py, which an operator passes and a member does not -- so this file simply links, and the route decides. What a row carries no action for is the *enrollment*: removing someone from a challenge is not a moderation power the server grants (see app/permissions.py -- an admin gets reach and lifecycle, never authorship), so there is no sheet here and no data attributes for one. -#} {% for e in enrollments %}
