# پوستهٔ اندروید — Capacitor

## این چیست، و چه چیزی نیست

`mobile/` یک **پوسته** است، نه یک اپ دوم. هیچ صفحه‌ای نمی‌سازد، هیچ داده‌ای
نمی‌خواند و هیچ نسخه‌ای از UI ندارد: یک WebView است که `serverUrl` را باز
می‌کند و همان سایت را نشان می‌دهد — همان کوکی سشن، همان service worker، همان
صفحه‌های SSR. کل `app/` بی‌خبر از وجود این پروژه است، جز یک بلوک کوچک در
`app/static/js/app.js` که در مرورگر بی‌اثر است.

سه چیز را اضافه می‌کند که وب نمی‌تواند بدهد و بنابراین دلیل وجودش هستند:
پوش بومی (فاز ۳)، آیکون و اسپلش واقعی، و یک صفحهٔ محلی وقتی سرور اصلاً در
دسترس نیست — چون یک اپ نصب‌شده نوار آدرس ندارد و پیام خطای خود WebView در آن
بن‌بست است.

**نکتهٔ انتشار:** کافه‌بازار اپ‌هایی را که «صرفاً نمایش‌دهندهٔ یک وب‌سایت»
هستند رد می‌کند. چیزی که این پرونده را قابل قبول می‌کند پوش بومی است — یعنی
فاز ۳ اختیاری نیست، شرط انتشار است.

## چیدمان

```
mobile/
  app.config.json      ← تک‌منبع حقیقت (پایین را ببین)
  capacitor.config.js  ← پیکربندی پوسته؛ app.config.json را می‌خواند
  scripts/
    apply-config.mjs   ← www/server-url.js را از همان فایل می‌سازد
  www/
    index.html         ← تنها صفحهٔ محلی: «به سرور وصل نشدیم»
    server-url.js      ← تولیدشده
  android/             ← پروژهٔ اندروید
```

## تک‌منبع حقیقت: `app.config.json`

هر مقداری که بین «پوسته‌ای که رویش توسعه می‌دهم» و «پوسته‌ای که منتشر
می‌کنم» فرق دارد در همین یک فایل است:

| کلید | چه کسی می‌خواندش |
|---|---|
| `serverUrl` | `capacitor.config.js` (آدرس WebView و `allowNavigation`)، و `scripts/apply-config.mjs` که آن را در صفحهٔ محلی می‌نویسد |
| `appId` | `capacitor.config.js` و `android/app/build.gradle` (`applicationId`) |
| `appName` | `capacitor.config.js` → `res/values/strings.xml` |
| `versionName` / `versionCode` | `android/app/build.gradle` |

هیچ‌کدام از این‌ها جای دومی تایپ نشده‌اند. عوض کردنشان یعنی ویرایش این فایل و
بعد `npm run sync`.

## دستورها

همه از داخل `mobile/`:

```bash
npm install          # یک بار
npm run sync         # config را اعمال می‌کند و پروژهٔ اندروید را به‌روز می‌کند
npm run open         # پروژه را در Android Studio باز می‌کند
```

آیکون‌های لانچر (فقط بیت‌مپ‌های API ۲۳–۲۵) از ریشهٔ مخزن ساخته می‌شوند:

```bash
.venv/Scripts/python -m app.scripts.generate_android_icons
```

بقیهٔ نشان‌ها — آیکون تطبیقی، اسپلش، آیکون اسپلش اندروید ۱۲ — همگی
`<vector>` هستند و دستی کنار هم نوشته شده‌اند، پس هیچ چگالی‌ای برای
بازتولید ندارند.

## چه چیزی از وب‌اپ تغییر کرد

فقط `app/static/js/app.js`، و فقط دو کار که یک صفحه داخل WebView نمی‌تواند به
مرورگر بسپارد:

* **رنگ نوار وضعیت.** تم اندروید فقط می‌تواند به ترجیح *دستگاه* جواب بدهد
  (`values/` و `values-night/`). حالت سومِ این اپ — انتخاب صریح «روشن»/«تاریک»
  روی گوشی‌ای که برعکس تنظیم شده — را هیچ qualifier‌ای بیان نمی‌کند، پس
  `paintNativeChrome()` آن را در زمان اجرا می‌برد و `setTheme` صدایش می‌زند.
* **بستن اسپلش.** اسپلش یک پنجرهٔ native است و باید بشنود که صفحه آمد.

هر دو در مرورگر بلافاصله برمی‌گردند، چون `window.Capacitor` وجود ندارد.

## چه چیزی در پروژهٔ اندروید دست‌کاری شده، و چرا

* **`MainActivity.java`** تنها کد native این پروژه است و یک چیز را تصحیح
  می‌کند: Capacitor صفحهٔ خطای محلی را هم روی خطای شبکه و هم روی خطای HTTP
  نشان می‌دهد. دومی برای این اپ غلط است — ۴۰۴ اینجا یک جواب طراحی‌شده با
  صفحهٔ خودش است (پروفایل کس دیگر، صفحهٔ ادمین، گروهی که عضوش نیستی) — پس
  نیمهٔ HTTP خالی override شده و نیمهٔ شبکه دست‌نخورده مانده.
* **`build.gradle`** به‌جای مقادیر ثابت `app.config.json` را می‌خواند، و بلوک
  `google-services` حذف شده: این اپ هرگز `google-services.json` نخواهد داشت،
  چون FCM از ایران قابل اتکا نیست و پوش از دروازهٔ بومی می‌رود.
* **پوش وب اینجا کار نمی‌کند، و عمداً چیزی برایش اضافه نشده.** وب‌اپ از
  نسخهٔ نصب‌شدهٔ PWA اعلان روی دستگاه می‌فرستد (بخش «Push» در `CLAUDE.md`)،
  اما WebView اندروید اصلاً `PushManager` ندارد؛ پس `initPushSwitch()` در
  این پوسته هیچ ردیفی را نشان نمی‌دهد و عضو، سوییچی که کار نکند نمی‌بیند.
  راه اندروید برای پوش امروز همان نصب PWA است، و نیمهٔ دیگرش دروازهٔ بومی
  بالاست که هنوز ساخته نشده.
* **`AndroidManifest.xml`**: `allowBackup=false` (این اپ کوکی سشن دارد)،
  `screenOrientation=portrait` (همان چیزی که manifest وب می‌گوید)،
  `usesCleartextTraffic=false`، و فقط یک مجوز — `INTERNET`. هر مجوز اضافه‌ای
  سؤالی است که داور بازار می‌پرسد.
* **`res/`**: یازده `splash.png` قالب Capacitor و پنج
  `ic_launcher_foreground.png` حذف و با `<vector>` جایگزین شدند. رنگ‌ها از
  `styles.css` کپی شده‌اند (یک PNG نمی‌تواند CSS variable بخواند) و در
  `values/colors.xml` + `values-night/colors.xml` هستند.
* **`android/.gitignore`**: دو خط keystore از حالت کامنت درآمدند. کلید امضا
  هرگز نباید در مخزن باشد.
* **`adjustMarginsForEdgeToEdge: "auto"`** در پیکربندی: اندروید ۱۵ هر اپی را
  که `targetSdk 35` دارد edge-to-edge می‌کند و این layout برایش ساخته نشده —
  نوار بالای اپ زیر ساعت گوشی می‌رفت.

## فازهای بعدی

* **فاز ۲ — بیلد و تست روی دستگاه.** نصب JDK 21 و Android SDK، ساخت APK
  دیباگ، و آزمودن چیزهایی که فقط روی دستگاه معلوم می‌شوند: ماندگاری کوکی سشن
  بین اجراها، دکمهٔ back سخت‌افزاری، `<input type="file">` آواتار، ثبت
  service worker داخل WebView (گزینهٔ `resolveServiceWorkerRequests` را آنجا
  بسنجید)، و **فونت Vazirmatn که از `fonts.googleapis.com` می‌آید** — داخل
  ایران این کندی یا شکست است و در اپ نصب‌شده خیلی بیشتر از مرورگر به چشم
  می‌آید.
* **فاز ۳ — پوش بومی.** پوشه یا نجوا. اضافه‌شدن `POST_NOTIFICATIONS` به
  manifest، و باز شدن اپ روی صفحهٔ درست وقتی نوتیفیکیشن لمس می‌شود.
* **فاز ۴ — انتشار.** keystore، امضای release، و چک‌لیست پایین.

## چک‌لیست انتشار

پیش از ساخت اولین APK منتشرشدنی، این‌ها باید انجام شوند:

1. **`appId` را عوض کنید.** الان `run.liara.challenges` است، که آدرس فاز
   توسعه است. شناسهٔ بسته پس از اولین انتشار در بازار **هرگز** قابل تغییر
   نیست — عوض کردنش یعنی یک اپ کاملاً جدید با صفر نصب. مقدار پیشنهادی:
   `ir.chalesh.app`. کافی است `app.config.json` ویرایش شود؛ `namespace` در
   `build.gradle` (نام پکیج جاوا) می‌تواند همان بماند، چون کاربر و فروشگاه
   آن را نمی‌بینند.
2. **`serverUrl` را به دامنهٔ اختصاصی ببرید.** آدرس لیارا داخل APK منتشرشده
   قفل می‌شود؛ عوض کردنش بعداً یعنی آپدیت اجباری برای همه.
3. `versionCode` را ۱ واحد بالا ببرید (بازار نسخهٔ تکراری را قبول نمی‌کند).
4. keystore بسازید، بیرون از مخزن نگه‌ش دارید، و **از آن نسخهٔ پشتیبان
   بگیرید** — گم شدنش یعنی دیگر هرگز نمی‌توانید همین اپ را آپدیت کنید.
5. `webContentsDebuggingEnabled` باید `false` بماند.
